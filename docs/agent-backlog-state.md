## Iteration #23 — 2026-07-31 (Spec 055: Kokoro offline-voice spike — a fixture-backed verdict, no ears)

**Live state:** PR **#47** (spec 054) is **MERGED** — merge commit `fba227a`, all 7 required checks green on head `8105b4f`. `origin/main` = `fba227a`. Branch `055-kokoro-offline-voice` off that head; diff is `specs/055-kokoro-offline-voice/**`, `src/lib/kokoro-word-timings.ts`, `src/__tests__/**`, plus this doc — no `src-tauri/`, no `.github/workflows/`, no new dependency, so it is self-merge class.

- **The verdict is mechanical, and it is a NO for the obvious path.** Kokoro's **Python** `KPipeline` satisfies Lectrice's karaoke contract; the **JavaScript/ONNX** port — the one that would otherwise be the natural fit for a Tauri bundle — does not, and the gap is **≥ 0.44 s** of highlight error. Adoption is therefore gated on shipping an embedded Python interpreter or sidecar, which is a real packaging cost, not a "looks promising". Full write-up: `specs/055-kokoro-offline-voice/decision.md`.
- **Evidence is two committed captures of real Kokoro output**, taken once by `specs/055-kokoro-offline-voice/capture-kokoro.py` (kokoro 0.9.4, `hexgrad/Kokoro-82M`, voice `af_heart`, 24 kHz) and cache-keyed `sha256("kokoro|<lang>|<voice>|<text>")` so a re-capture with any input changed is a new key, not a silent overwrite: single-chunk `8fc1e6fd…` (2.600 s) and multi-chunk `cf1d72df…` (4.025 s). `pnpm exec vitest run src/__tests__/integration/kokoro-word-timings.test.ts` → **9 passed**, offline: no model call, no weight download, no audio device.
- **The load-bearing finding is undocumented upstream: Kokoro's timestamps are chunk-relative.** `KPipeline` splits on `\n+` and **restarts its clock at zero every chunk**. In the multi-chunk capture, `delta` reports `start_ts: 0.3` with 1.9 s of audio ahead of it — a pass-through adapter would highlight `delta` *before* `alpha` (real mark 0.350 s). A single-chunk fixture could not have exposed this; capturing the second one is what turned the spike from a shrug into a verdict.
- **Second trap: the split separator is in no token.** The last token of a chunk carries `whitespace: ""`, so `text + whitespace` concatenation yields `"…gammadelta…"`. Character offsets must be re-anchored per chunk against the source; otherwise every offset after a newline is off by one, i.e. the highlight sits on the wrong glyph for the rest of the page. Offsets are UTF-16 code units, matching `chars_to_words` in `src-tauri/src/ai_tts/elevenlabs.rs`.
- **"The highlight index derives from `start_time`" is proved through the SHIPPING loop**, not a re-implementation: converted timings drive `useTtsWordHighlight` + `ai-tts:playback-starting` + `useTtsHighlightStore` with `performance.now` spied and `requestAnimationFrame` stubbed into a manual frame queue (the `karaoke-sync.test.ts` harness). Leading silence clamps to index 0, every word becomes current on the first frame at/after its own `startTime`, the last word holds through trailing silence, and the duration guard completes exactly once.
- **The cost of a timestamp-less runtime is a number, not an adjective: 0.4433 s / 0.4778 s.** `uniformApproximationError` models the *generous* fallback (length-weighted proportional spread per chunk) and measures the worst distance from Kokoro's real marks — so those figures are a **floor**. The shortest word span in these captures is 0.300 s, so the approximation is off by more than a whole word. Both pinned to 3 dp. **The bound:** error cannot accumulate — each chunk re-anchors to real audio length — but a "chunk" is a `\n+` segment, **not a sentence**, so on a paragraph rendered as one line the bound is the whole paragraph unless the caller passes a sentence-level `split_pattern`.
- **Every assertion is shown able to fail.** NC1 (drop the chunk time offset) → **4 failed / 5 passed**, and it reproduces the exact predicted error: `expected 0.3 to be close to 2.1999999999999997, received difference is 1.8999999999999997`. NC2 (single running char cursor instead of re-anchoring) → **2 failed / 7 passed**. Baseline brackets both → **9 passed**, so the restore is proved rather than assumed. (Shell gotcha, again: `cp` is aliased to `cp -i` and silently no-ops a restore — use `command cp -f`.)
- **The blocker that nearly killed the capture was mine, not Kokoro's.** `espeakng-loader` bakes its build machine's path into the shipped `.so`, so phonemization died on `Error processing file '/home/runner/work/espeakng-loader/.../phontab': No such file or directory.` An earlier session called it "a phonemizer/espeak-ng defect" — **wrong**. Reading `phonemizer/backend/espeak/{wrapper,api}.py` showed `misaki` sets `EspeakWrapper._ESPEAK_DATA_PATH` at import time and class attributes **win over** `PHONEMIZER_ESPEAK_DATA_PATH` (and the earlier env attempt used the wrong name, `PHONEMIZER_ESPEAK_DATA`). Fix: call `EspeakWrapper.set_library`/`set_data_path` with the nixpkgs espeak-ng paths **after** importing kokoro. The `kokoro-speakd` nix flake build was never needed.
- **Adversarial gate — `glm-review` (DeepInfra `moonshotai/Kimi-K2.6`), family-diverse against an Anthropic author, and it earned its keep.** Of 6 findings, **2 named real gaps and 4 were rejected after checking the cited lines against the real files**. In both surviving cases the reviewer's *proposed remedy* was wrong and the *gap underneath it* was real, so the guards are mine, not its: (1) the whole offsetting scheme assumes a token's mark and its chunk's audio share a timebase — that assumption was load-bearing and unasserted, so conversion now throws when a mark falls outside its own chunk's audio; (2) if Kokoro ever dropped a segment, conversion would have succeeded cleanly with the missing words simply absent from the timeline, so it now throws when non-whitespace source text sits between two chunks. Each guard has its own negative control: disabling either turns exactly its test red (**1 failed / 10 passed** each), baseline **11 passed**. The review also forced `decision.md` Finding 4 to say *why* start error is the measured quantity — `findWordIndexAtTime` selects from `startTime` boundaries, so end error is neither measured nor claimed. Landed in PR **#48**, merge commit **`49809d2`**.
- **Explicitly NOT established** (stated in `decision.md` rather than glossed): ◐ that `kokoro-js` *specifically* lacks per-token marks (taken from its documented output shape, not re-run here — the 0.44 s applies to any runtime without marks either way); ◯ audio quality, pt-BR coverage, real-time factor (prior research measured ~3.3× real time; not re-measured, so not quotable as current); ◯ that an embedded Python runtime is bundleable at acceptable size/start-up — that is the open cost handed to whoever picks up adoption.
